# XrTopoR

Редактор печатных плат с топологическим трассировщиком в духе TopoR: трассы под любым углом и дугами,
без сетки, топология первична — геометрия вычисляется из неё. Интерфейс повторяет TopoR 7.0 (меню, панели,
горячие клавиши, проекты `.fsproj`). C++26, Qt 6, CGAL, Boost.

## Сборка

```sh
cmake --preset release          # GCC 16 из /opt/gcc-16, C++26
cmake --build --preset release
ctest --preset release          # юнит-тесты + GUI-тесты (offscreen)
```

Нужны Qt 6 (Widgets, Concurrent, Network, OpenGL, OpenGLWidgets; для значков — плагин SVG), Boost.JSON, CGAL,
для тестов — GoogleTest. Цели: `xrtopor` (GUI), `xrtopor-cli`, библиотеки `xrgeom`, `xrcore`, `xrio`, `xrdrc`,
`xrtopo`, `xrrouter`, `xrgui`.

Готовые сборки для Linux и Windows — в [Releases](https://github.com/XRay3D/XrTopoR/releases) (см. «Сборки и выпуски»).

## Форматы

| Формат | Чтение | Запись |
|---|---|---|
| KiCad `.kicad_pcb` (6–11) + `.kicad_pro` (классы цепей) | да | да (исходный файл патчится: размещение и разводка, остальное сохраняется) |
| P-CAD 2002 ASCII `.pcb` | да | да (исходный файл патчится: размещение, проводники, переходы, заливки из областей металлизации; библиотеки, цепи, слои, тексты сохраняются) — только для платы, прочитанной из P-CAD |
| TopoR PCB `.fst` (1.2.0) | да | да |
| Проект TopoR `.fsproj` | да | да (документы, папки, варианты автотрассировки) |
| TopoR `.fsx` (бинарный) | через `.fst` рядом | — |
| Specctra `.dsn` / `.ses` | да | да |
| Gerber RS-274X (X2) + Excellon | — | да |
| SVG (просмотр), BOM `.csv` | — | да |

Рядом с платой хранится её топологическая модель `<плата>.xrtopo`: F5–F7 продолжают с неё, а не строят заново.

## CLI

```sh
xrtopor-cli --version
xrtopor-cli info     board.kicad_pcb
xrtopor-cli convert  board.pcb out.fst                       # в любой записываемый формат по расширению
xrtopor-cli drc      board.fst [--max N] [--nominal]
xrtopor-cli route    board.dsn -o routed.ses [--passes 6] [--via-cost 3] [--no-vias] [--layers 0,1] [--nets a,b]
                     [--keep] [--soft] [--buses] [--no-optimize] [--no-refine] [--no-fill] [--svg out.svg]
xrtopor-cli reshape  board.fst -o out.fst --model            # F5 на топологической модели
xrtopor-cli refine   board.fst -o out.fst --model            # F6
xrtopor-cli optimize board.fst -o out.fst --model            # F7
xrtopor-cli fill     board.fst -o out.fst                    # залить области металлизации (unfill — снять заливку)
xrtopor-cli flexfix  board.fst -o out.fst --nets a,b [--off] # гибкая фиксация цепей
xrtopor-cli report   board.fst [--bom out.csv]               # длины по слоям и цепям, переходы, BOM
xrtopor-cli import-ses board.dsn routes.ses -o out.dsn
xrtopor-cli gerber   board.kicad_pcb outdir/
xrtopor-cli svg      board.kicad_pcb out.svg
```

Полный список ключей — `xrtopor-cli` без аргументов.

## GUI: горячие клавиши (как в TopoR)

| Клавиша | Действие |
|---|---|
| `R` | прокладка проводника (см. ниже) |
| `V` | при прокладке — переход и смена слоя; иначе постановка переходов |
| `L` | при прокладке — переход на следующий слой; с выделенными проводниками — перенести их на другой слой (при двух слоях — сразу, иначе меню слоёв); без выделения — следующий активный слой |
| `1`…`9`, `0` | активный медный слой (0 — нижний) |
| `;` / `Q` | при прокладке — довести проводник до ближайшего соединения / выбрать другую цель |
| `O` | вкл/выкл ограничение углом 45° при прокладке |
| `W` | ширина проводника |
| `C` | спрямить |
| `F` | фиксировать / расфиксировать |
| `X` | циклическое выделение: сегмент → проводник → цепь |
| `Z` | залить / снять заливку выделенных областей |
| `Backspace` | убрать последний сегмент при прокладке |
| `Esc` | отмена прокладки / режим выделения |
| `Space`, `Shift+Space` | повернуть на −90° / +90° |
| `Del` | удалить выделенное |
| `N` | показать/скрыть связи |
| `Shift+S` | только активный медный слой |
| `Ctrl+B` | показать плату целиком |
| `Ctrl+M` | линейка |
| `F5` / `F6` / `F7` | расчёт формы / перекладка / подвижка (см. ниже) |
| `F8` | Freestyle: перемещение с раздвиганием |
| `F9` | DRC |
| `F11` | автотрассировка (варианты, в фоне) |
| `Ctrl+Z` / `Ctrl+Y` | отмена / повтор |
| колесо / средняя или правая кнопка с перемещением | масштаб / панорамирование |

Горячие клавиши настраиваются в «Настройки программы» и переносятся из установленного TopoR.

**Прокладка (`R`).** Первый щелчок включает «Проводники» в фильтре выделения. Щелчок по контакту, переходу или
проводнику — начало, щелчки — точки. Ввод заканчивается щелчком по контакту, переходу или проводнику своей цепи
(в том числе того, с которого начали, — петля), `Enter`, двойным щелчком или правой кнопкой; инструмент при этом
остаётся включённым. Вводимый сегмент у своего проводника сразу «примагничивается» к его оси; краснеет, если
нарушает зазор (онлайн-DRC). Новые проводники и переходы вносятся в топологическую модель.

## Автопроцедуры и трассировщик

Плата живёт вместе со своей **топологической моделью** (`src/topo`): ограниченная триангуляция Делоне (CGAL) по
контактам, переходам и контуру на каждом слое, проводники — пути по её рёбрам с порядком пересечений. Правки в
редакторе модель доводит, а не строит заново; геометрию проводников из неё рисует реализатор.

- **F5 «Расчёт формы проводников»** — модель к взвешенной точке Делоне, проводники рисуются из неё: касательные
  отрезки и дуги, место на рёбрах делится по силам; точки ветвления — в равновесие.
- **F6 «Перекладка проводников»** — проводники перекладываются более дешёвыми путями по треугольникам (между
  другими проводниками, если нужно), клинчи разбираются, лишние переходы снимаются; затем, по желанию, смена слоёв.
- **F7 «Подвижка»** — переходы и точки ветвления (и, по желанию, компоненты) сдвигаются, укорачивая проводники.
- **Номинальный зазор** правил соблюдается там, где есть место; минимальный — только в тесных местах.
- **Автотрассировка F11** (`src/router/topo`): A* по состояниям триангуляции с проверкой планарности, негоциация
  перегрузок рёбер (PathFinder), rip-up & reroute, шины, затем реализация, DRC, F7 и F6. Ищет варианты, пока не
  остановлена; лучший открывается в редакторе, любой — добавляется в проект.

## MCP-сервер (для ИИ-агентов)

Редактор может работать как MCP-сервер (Model Context Protocol): агент читает, правит и разводит открытую плату
теми же процедурами, что и пользователь, каждая его правка — шаг «Отменить». По умолчанию выключен.

```sh
xrtopor --mcp board.fst          # HTTP на http://127.0.0.1:7417/mcp на этот запуск (--mcp 7420 — другой порт)
xrtopor --mcp-stdio board.fst    # JSON-RPC построчно на stdin/stdout (клиент сам запускает процесс; не в Windows)
```

Постоянно — «Настройки программы › Общие › MCP-сервер». Слушает только 127.0.0.1; запросы со страниц других
сайтов (заголовок `Origin`) отклоняются. Claude Code подключается через `.mcp.json` в корне репозитория, описание
работы для агента — `.claude/skills/xrtopor/SKILL.md`.

Инструменты: `info`, `open`, `save`; `nets`, `net`, `components`, `component`, `ratsnest`, `region`, `rules`, `log`;
`route` (связь по топологической модели, как инструмент «Прокладка»), `add_track`, `add_via`, `delete`, `unroute`,
`move_component`, `fix`, `flex_fix`, `undo`, `redo`; `autoroute` (F11), `autoroute_variants`, `autoroute_open`,
`reshape` (F5), `refine` (F6), `optimize` (F7), `drc`, `fill`, `job`; `screenshot`, `view`, `select`, `set_layer`,
`commands`, `command`. Координаты в мм.

## Сборки и выпуски

GitHub Actions (`.github/workflows/release.yml`, как в GERBER_X3) собирает XrTopoR для Linux (Debian sid, GCC 16) и
Windows (MSYS2 UCRT64) и выкладывает самодостаточные архивы в Releases:

- каждый push в `main` — пред-выпуск `continuous`;
- тег версии — выпуск этой версии: `git tag 0.2 && git push origin 0.2`.

Версия, ветка или тег, коммит и дата сборки — в «Справка › О программе» (кнопка «Скопировать сведения») и в
`xrtopor --version`, `xrtopor-cli --version`; номер версии — `project(... VERSION)` в `CMakeLists.txt`.

При запуске редактор спрашивает у GitHub последний выпуск (пред-выпуск `continuous` не в счёт) и о более новом
сообщает один раз, со ссылкой на его страницу; в «О программе» — то же при каждом открытии и галочка
«Проверять обновления при запуске».

## Отладка

Переменные окружения: `XR_PROF=1` — профиль процедур, `XR_THREADS=N` — число потоков, `XR_SKETCH=1` —
топологические эскизы автотрассировщика вместо геометрии, `XR_TOPO_DEBUG`, `XR_FS_DEBUG`, `XR_CHECK` — проверки
и вывод модели, F5–F7 и Freestyle. Остальные — `grep -r 'getenv("XR_' src`.
