# XrTopoR: разводка через MCP

Сервер живёт в самом редакторе и работает с той платой, что открыта в его окне. Пользователь видит каждую правку,
каждая правка — один шаг «Отменить» (его Ctrl+Z отменяет и мои правки).

## Подключение

- Инструменты сервера называются `mcp__xrtopor__*`. Если их нет — сервер не запущен или не подключён:
  - запустить редактор с сервером: `xrtopor --mcp файл` (порт из настроек, по умолчанию 7417; `--mcp 7420` — другой),
    либо пользователь включает «Настройки программы › Общие › MCP-сервер»;
  - в репозитории лежит `.mcp.json` с `http://127.0.0.1:7417/mcp`; вне репозитория:
    `claude mcp add --transport http xrtopor http://127.0.0.1:7417/mcp` (это делает пользователь);
  - клиент, который сам запускает процесс: `xrtopor --mcp-stdio файл` (с `QT_QPA_PLATFORM=offscreen` — без окна).
- Сборка: `~/build/XrTopoR-release/apps/xrtopor`. Без окна (`offscreen`) работают все инструменты, снимок тоже.
- Свой экземпляр для проверок запускать на отдельном порту, в отдельном `XDG_CONFIG_HOME` из scratchpad, и
  останавливать по PID процесса на этом порту (`ss -ltnp`), не `pkill xrtopor` — там же может работать редактор
  пользователя.

## Соглашения

- Координаты и длины — мм, система платы (Y вниз).
- Цепь — по имени; компонент — позиционное обозначение; контакт — `"U1.3"`; проводник и переход — устойчивый id
  (`track:12`, `via:5` в ответах; в аргументах `tracks: [12]`, `vias: [5]`, конец связи `"via:5"`). Индексы не
  использовать — они меняются от правки к правке.
- Слой — по имени (`F.Cu`, `Top`, …) или `top` / `bottom`.
- Процедура (autoroute, refine, optimize) идёт одна; вызов ждёт `wait_s` секунд, иначе отвечает состоянием —
  дальше `job(wait_s=…)`, остановить — `job(stop=true)`.

## Порядок работы

1. `info` — что открыто, слои, неразведённые связи, есть ли несохранённые правки. Нет платы — `open(path)`.
2. `ratsnest` / `nets(unrouted_only=true)` — что развести; `net(name)` — контакты, правила ширины и зазора по слоям.
3. Целиком — `autoroute(variants=N)`: лучший вариант открывается в редакторе; варианты — `autoroute_variants`,
   другой — `autoroute_open`. Частично — `autoroute(nets=[…], keep_routing=true)`.
4. Вручную — `route(from, to[, layer])`: как инструмент «Прокладка» редактора, по топологической модели, чужие
   проводники раздвигаются. Без `layer` пробует все слои, где есть оба конца. Контакты на разных слоях (SMD сверху
   и снизу): `route` до точки → `add_via` там → `route` от `via:id`.
5. Довести форму: `reshape` (F5), `refine(layers=true)` (F6), `optimize(refine_after=true)` (F7).
6. `drc` — нарушения по типам и первые из них с координатами и объектами; `screenshot(x, y, width)` — посмотреть
   место (картинка как в окне пользователя: его слои и схема отображения).
7. Поправить: `delete(tracks|vias|nets)`, `unroute(nets)`, `move_component`, `fix`, `flex_fix`; не вышло — `undo`.
8. Переназначение: `swap()` — группы функционально эквивалентных контактов (`swap(gates=true)` — вентилей);
   `swap(a="D3.1", b="D3.2")` меняет цепи двух контактов одной группы и перебрасывает концы их проводников,
   `swap(a, b, gates=true)` — два вентиля целиком. После обмена проводники обычно пересекаются: `reshape`/`refine`.
   Цепи из одного контакта убирает `command("Cmd_RemoveSinglePinNets")`.
9. `save()` в свой файл или `save(path)` («Сохранить как», файл добавляется в проект).

## Грабли

- «No way … the copper area of GND is poured on B.Cu»: залитая область чужой цепи закрывает слой. `fill(action=
  "clear")`, развести, `fill(action="pour")` — или другой слой.
- `reshape` останавливается на топологических нарушениях (пересекающиеся проводники) и ничего не меняет: в ответе
  `violations`, проводники выделены в редакторе. Удалить/переложить их и повторить.
- `open` отказывает при несохранённых правках: сначала `save`, или `open(discard=true)` — только если пользователь
  согласен их потерять.
- `command(id)` запускает команду меню по её id из `commands`; команды с диалогами отклоняются — для них есть
  свои инструменты (`open`, `save`, `drc`).
- Правки сервера и пользователя в одной истории отмены: `undo` отменяет последнюю правку, чья бы она ни была —
  смотреть `info.undo.next_undo` перед `undo`.
- F6 после свежей автотрассировки может ответить «переложено 0 из 0» — это значит, что перекладывать нечего, а не
  ошибка сервера.

## Без редактора

Пакетно над файлом, без окна и сервера — `~/build/XrTopoR-release/apps/xrtopor-cli`:
`info`, `drc`, `route -o out`, `reshape|refine|optimize --model -o out`, `fill`, `report`, `svg`
(полный список — запуск без аргументов). Результат пишется в новый файл; исходный не трогать.
