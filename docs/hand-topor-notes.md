# Что известно о внутренностях TopoR из `hand/` и что из этого перенесено

`hand/` — реконструкция (по декомпиляции DLL TopoR Lite 7.0) модели и алгоритмов F5–F7 и сеточный стенд
автотрассировки. Разбор 2026-11-02, три прохода по файлам; здесь выжимка и сравнение с XrTopoR.

## Модель TopoR (br_model.hpp)

- Одна **триангуляция** на слой над «owners»: площадки, переходы, свободные вершины проводников (изломы,
  ветвления) и отрезки-препятствия. Owner — капсула `coord + vec + width`; угол треугольника — не точка,
  а **положение вдоль оси owner'а** (`chainPos`, `vertexAt`). У переходов и круглых КП `vec = 0`.
- Проводники живут на рёбрах: пересечения ребра считаются (`arcBusy`) и цепляются списком
  (`cycleLink → jogNext`); отрезок, лежащий вдоль ребра, — `cycleLink` при `arcBusy == 0`.
  `jogMode[owner]` = степень вершины (1 излом, 3 ветвление, 4 пара).
- Стоимость ребра — `metric_distance(style)` по стилю формы (any-angle: `max(L∞, L1/√2, L2 − 2644)`,
  octiline, curviline — заглушка). Класс серьёзности ребра (биты 4–5) — стоимость против бюджета ширин
  `{lo, mid, hi}` (в реконструкции бюджет — заглушка `{w, w, w}`). Единицы 0.1 мкм.

## F5 / F6 / F7 — одна петля (`cascade_100a30`, f6_refine.cpp)

- Расписание: `tolLocal = 30000·0.8^k` (3 мм → 10 мкм), ~28 итераций. F5 — без «интенсивности»,
  F6 — 1, F7 — 1 (0x8002/0x8003) или 2 (0x8001, с компонентами) плюс `jog_repair_loop` на итерациях 9–14.
- Итерация — **силовая релаксация**: по рёбрам с ненулевым классом единичный вектор (×16 / ×64 по классу)
  накапливается в сдвиг объектов на концах; шаг на объект адаптивный (Rprop: ×1.5 при том же направлении,
  ×0.6 при развороте), ограничен `tol·scale`, применяется с проверкой столкновений: безопасная часть,
  остаток переносится, при упоре скольжение вдоль перпендикуляра к блокеру с усадкой 0.9
  (`pull_slot_106400`), блокер сам становится движимым (`grid_snap_106a90`). Стадии: изломы, переходы,
  jog-вершины, компоненты.
- Затем очередь флипов Лоусона с тестом Делоне с учётом ширин (`geom_1218c0`, `102300`), релаксация
  углов треугольника (`107cf0`), обработчики по степени: излом спрямляется/удаляется (`113660`),
  ветвление перестыковывается по наименьшей сумме длин трёх вариантов (`11c940`), пара меняется
  (`11be10`); подрезка ширин по лестнице (`jog_drain_119f90`).
- **Чего там нет**: поиска путей, rip-up, смены слоя, удаления переходов, устранения чётных пересечений
  и — для F5 — геометрии дуг/радиусов/выходов из КП: конечная форма проводника строится где-то ещё.
  «Arc» в реконструкции — ребро триангуляции, «jog pair» — запись сегмента/пересечения.
- `jog_repair_step` (F7, `(vh1+vh2)/2`): vh1/vh2 — два других угла треугольника owner'а; по файлу TopoR
  после F7 (`tests/data/topor/Example_04/Arcs_master_f7.fst`) переход садится на прямую своего
  проводника — у нас это кандидат «прямо сквозь переход» в подвижке.
- Состояние реконструкции: 33 пустых `pending_*`, бюджеты и зазоры угаданы, дефекты в `move_refine`
  (теряется запрошенный сдвиг) и `candidate_gen`. Гарнесс `postproc` строит из .fsb линейные цепочки без
  триангуляции — на реальной плате стадии пустые, цикл выходит после первой итерации. `autoroute.cpp` —
  самодельный сеточный Дейкстра (не TopoR), маршрут в выходной .fsb не пишет.

## Что перенесено в XrTopoR и что измерено

| Что | Результат |
|---|---|
| Порядок проводников на ребре по топологии (расхождение путей), а не по положению эскиза | commit 1145eeb; эталонные разводки без изменений, автотрассировка лучше |
| Переход «прямо сквозь» (середина соседних вершин, медиана), толчок от тесноты, соседи перекладываются вместе | commits c4b828d, f9f3cc7, 84fdecf |
| Ширина меняется → цепочка кончается (ветка 0.3 мм от шины 0.8 мм) | Arcs F5 33 → 18, F7 28 → 12 |
| **Релаксация F7 по TopoR** (силы, Rprop, расписание, скольжение, глобальная перекладка на итерации) | `optimize --relax`; хуже перебора: Arcs 19 против 12, arz 17 против 10 — у нашего реализатора перекладка всей платы не неподвижная точка (F5 от результата F5: arz 14 → 25, 7 КЗ в ряду переходов) |
| Перекладка окрестности (`reshape --around`) | хуже: одна цепь Arcs с окрестностью 1 мм 33 → 142; проводник, уложенный отдельно против неподвижных соседей, теряет вложенность |

## Сравнение на Arcs_master.pcb (наш DRC, длина по .fst)

| Шаг | TopoR Lite 7.0 | XrTopoR |
|---|---|---|
| импорт P-CAD | 7338.9 мм, 84 наруш. (DRC TopoR) | 43 (наш DRC) |
| F5 | 6495.8 мм, 55 | 6375.0 мм, 18 |
| F6 (от импорта) | 6433.2 мм, 144 ПО, 35 (31 + 4 край) | — (наш F6 — поиск путей по сетке, другая вещь) |
| F5 → F7 | 6276.4 мм, 0 | 6348.1 мм, 12, 2.7 с |

Разрыв до TopoR — в реализаторе: укладка в плотных рядах переходов (стек радиусов), неидемпотентность
F5, артефакты локальной перекладки против неподвижных проводников. Силовой подход TopoR работает только
вместе с глобальной перекладкой, которая у них — неподвижная точка.
